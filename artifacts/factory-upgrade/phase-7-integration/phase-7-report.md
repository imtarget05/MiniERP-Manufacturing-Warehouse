## 1. Database Schema (sql/10_helpdesk_schema.sql)

Idempotent and rerunnable delivery outbox:

```sql
CREATE TABLE HELPDESK_DELIVERY (
  DELIVERY_ID NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  EXTERNAL_REF VARCHAR2(80) NOT NULL UNIQUE,
  OPERATION VARCHAR2(40) DEFAULT 'INCIDENT' NOT NULL,
  REQUEST_HASH VARCHAR2(64) NOT NULL,
  STATUS VARCHAR2(20) DEFAULT 'PENDING' NOT NULL
    CONSTRAINT CK_HD_STATUS CHECK (STATUS IN ('PENDING','SENT','FAILED','NOT_ENABLED','CONFLICT')),
  ATTEMPT_COUNT NUMBER DEFAULT 0 NOT NULL,
  LAST_ERROR VARCHAR2(1000),
  CORRELATION_ID VARCHAR2(60),
  CREATED_BY VARCHAR2(50) DEFAULT 'system' NOT NULL,
  CREATED_AT DATE DEFAULT SYSDATE NOT NULL,
  UPDATED_AT DATE DEFAULT SYSDATE NOT NULL,
  SENT_AT DATE
);
CREATE INDEX IX_HD_STATUS ON HELPDESK_DELIVERY (STATUS, UPDATED_AT);
```

## 2. Integration Service & Security (src/Services/)

- `HelpdeskOptions.cs`:
  - Configurable via `appsettings.json` or environment variables: `HELPDESK_INTEGRATION_ENABLED`, `HELPDESK_BASE_URL`, `HELPDESK_INTEGRATION_KEY`, `HELPDESK_TIMEOUT_SECONDS`, `HELPDESK_MAX_ATTEMPTS`, `HELPDESK_RETRY_DELAY_MS`.
  - Enforces safe clamping: timeouts (1..60s), attempts (1..5), delays (0..5000ms).
- `HelpdeskSecurity.Sanitize`:
  - High-security sanitizer that scrubs sensitive fragments (`bearer`, `eyj`, `password`, `passwd`, `token`, `secret`, `integration_key`, `connectionstring`, `user id=`, `data source=`, raw SQL `select`/`insert`/`update`/`delete`) and replaces them with `[REDACTED]`.
- `HelpdeskIntegrationService.cs`:
  - Uses typed `HttpClient` configured with timeouts.
  - Sends `X-Integration-Key` header and `Idempotency-Key` header with `request.ExternalRef`.
  - **Idempotency contract**: SHA-256 hash computed on canonical payload. Reused key with altered payload raises `CONFLICT` (`IDEMPOTENCY_CONFLICT`). Replayed request with identical hash immediately returns previous `SENT` without repeating HTTP calls (`duplicate: true`).
  - **Fail-Soft contract**: If Helpdesk is unreachable or times out, the service retries up to `MaxAttempts` with linear backoff, updates `HELPDESK_DELIVERY` status to `FAILED`, and returns `HelpdeskDeliveryResult` with `sent = false, errorCode = "DELIVERY_UNAVAILABLE"`. It **never throws** unhandled exceptions and **never rolls back** or corrupts the ERP business transaction.
